# HTML Surface Three 0.1.0 Implementation Plan

> **For Codex:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development for Task 1 and superpowers:verification-before-completion before every commit, PR, merge, and release claim.

**Goal:** Ship a stable `0.1.0` that scales beyond whole-scene raycasting and is straightforward for an English-speaking Three.js user to evaluate and install.

**Architecture:** Keep `HtmlSurfaceManager` as the only stable orchestration API. Add one optional constructor input that replaces only the roots passed to the existing recursive `Raycaster`; all hit resolution, occlusion, input routing, and ownership code remains unchanged.

**Tech Stack:** TypeScript, Three.js, Vitest/happy-dom, Playwright, Vite, npm trusted publishing, GitHub Actions.

---

### Task 1: Configurable raycast roots

**Files:**
- Modify: `tests/manager-input-integration.test.ts`
- Modify: `src/HtmlSurfaceManager.ts`

1. Extend the test harness so it may pass `raycastRoots` to the manager.
2. Add a test where a surface group is included and a nearer scene blocker is excluded; verify the DOM click is delivered.
3. Run `npm test -- tests/manager-input-integration.test.ts` and confirm the new test fails because the blocker still wins.
4. Add `raycastRoots?: readonly Object3D[]`, store the provided reference, and use it instead of `scene.children` when present.
5. Run the focused test and then `npm test`; confirm all tests pass.
