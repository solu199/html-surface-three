# HTML Surface Three 0.1.0 Design

## Goal

Make the existing core a credible stable install: keep its production-oriented interaction and lifecycle behavior, remove the documented whole-scene raycast ceiling, and explain the value clearly to English-speaking Three.js users.

## Product position

HTML Surface Three is the interaction and lifecycle layer for HTML textures on arbitrary Three.js meshes. Its value is the combination of scene-aware occlusion, exact UV/material binding, browser-native form and text input, pointer capture, multiple surfaces, and reversible cleanup. Texture generation remains a replaceable backend detail.

## Stable API change

Add `raycastRoots?: readonly Object3D[]` to `HtmlSurfaceManagerOptions`.

- Default: `scene.children`, preserving current behavior.
- The manager reads the supplied array on every route, so callers may update a mutable array as their scene changes.
- Roots are raycast recursively and should be non-overlapping.
- Every interactive surface and every occluder that should participate must be under one of these roots.
- An empty array intentionally disables pointer hits.

This is a constructor option, not a setter, callback, layer abstraction, or BVH integration. Those additions are unnecessary until real usage proves otherwise.

## Documentation and release

- Rewrite the stable API and limitations pages in English and update the README examples and positioning.
- Document automatic DOM invalidation; manual `invalidate()` remains available for non-observable paint changes.
- Verify against the supported Three.js releases already covered by the peer range (`>=0.184.0 <0.186.0`); npm currently reports `0.185.1` as latest.
- Promote `0.1.0-rc.2` to stable `0.1.0`, publish it under npm's `latest` tag, and keep the existing tag-driven trusted-publishing workflow.

## Verification

- One integration regression test proves that default roots still include ordinary scene blockers and that an excluded blocker no longer blocks a configured surface root.
- Run typecheck, unit/integration tests, builds, clean-consumer package verification, and browser tiers through CI.
- Review the feature diff before merge, then verify the tag workflow, GitHub Release, npm version, dist-tag, and clean install.

## Deliberately deferred

R3F and WebXR adapters, alternate UV channels, SkinnedMesh/InstancedMesh guarantees, custom raycast callbacks, and BVH integration. R3F is the strongest later adoption feature, but adding a new framework peer and lifecycle surface before the core's first stable release would enlarge the support contract without user evidence.
